Registro local de incidencias

Practica etiquetas, validación, eventos y cambios del DOM con datos ficticios.

Qué hace esta demostración

No es un sistema de tickets real: no hay servidor de aplicación, cuentas ni almacenamiento persistente. Los registros sólo existen en esta vista y se pierden al recargar.

Utiliza códigos y síntomas inventados. No escribas nombres de personas, contraseñas ni información de equipos de una organización.

La información de referencia está disponible sin JavaScript. El simulador interactivo necesita que el script local se cargue correctamente.

    Pruebas que puedes realizar

    1. Abre sin JavaScript y comprueba que la referencia y las instrucciones conservan sentido.
    2. Con JavaScript, intenta enviar un código inválido y usa el resumen de errores para corregirlo con teclado.
    3. Introduce pc-007 y una descripción sintética de al menos diez caracteres; comprueba el código normalizado.
    4. Incluye <dato> en el texto: debe mostrarse literalmente, sin convertirse en una etiqueta.
    5. Añade dos registros para el mismo activo, vacía la sesión y comprueba que la referencia estática permanece.
    6. Recarga: los registros locales no deben persistir. Prueba también foco visible, zoom y pantallas estrechas.

    Estas instrucciones definen expectativas. Registra por separado el navegador, versión y resultado real de tus pruebas. Este ejemplo no acredita conformidad completa con WCAG.
